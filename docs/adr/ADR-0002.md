# ADR-0002 — Arquitectura en tres capas con patrones State, Facade, Factory, DAO y Adapter

**Estado:** Aceptada

## Contexto

Hay que separar presentacion, negocio y datos y concentrar las reglas del turno.

## Decision

`presentacion` → `negocio` → `datos`, cada capa solo conoce la de abajo. State para el ciclo del turno (transicion invalida = 409), Facade (`FachadaReservas`) como unico punto de reserva, Factory (`FabricaTurnos`) para crear turnos consistentes, DAO (repositorios) y Adapter para SOAP/REST/IA.

## Consecuencias

Las reglas viven en un solo lugar y se prueban sin contenedor. Mas clases que un CRUD directo.
