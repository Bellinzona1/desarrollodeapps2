# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

MediConecta: a medical appointment system ("gestión de turnos") built as a university TP (UADE, Desarrollo de Aplicaciones II). It is a **Jakarta EE 10 WAR deployed on WildFly** with PostgreSQL. All code, identifiers, comments, docs and commit messages are in **Spanish** — keep new code and docs in Spanish and follow the existing naming (`Gestion*`, `Repositorio*`, `Recurso*`, `Manejador*`).

The deliverables are graded on Jakarta EE concepts (stateless vs stateful EJBs, layered architecture, design patterns, declarative security/transactions, JMS, SOAP/REST integration). Design choices in the code are intentionally tied to those criteria and are justified in `docs/arquitectura.md` and `docs/Entrega_Obligatoria_2.md` — read those before restructuring anything, and update them when behaviour changes.

Both need a running app + DB. When you add an endpoint, add checks to `smoke-test.sh`.
- CI: `.github/workflows/ci.yml` — job `calidad` (`mvn verify`), `migraciones` (Flyway twice on an empty Postgres), `punta-a-punta` (compose + `smoke-test.sh`).

Laura Fernandez via `profesionales.usuario`.
- **No secrets with defaults anywhere**: JWT secret from `mediconecta.jwt.secreto` / `MEDICONECTA_JWT_SECRETO` (random per boot if missing), demo password as above, DB credentials only in WildFly config / `.env` (gitignored; `.env.example` documents the keys). Never add a fallback secret back.
- The only runtime dependency is `jakarta.jakartaee-api:10.0.0` with scope `provided` (JUnit/parsson are `test`). ## Architecture

Strict three layers under `com.mediconecta`, each depending only on the one below:

- `presentacion` — thin JAX-RS resources (`@ApplicationPath("/api")` in `AplicacionRest`), input DTOs (`PedidoTurno`, `PasoReserva`), `ExceptionMapper`s (each a one-liner delegating to `Problemas`), `RecursoAutenticacion` (`POST /api/auth/login` → JWT), `RecursoSalud`, `RecursoMensajeria` (ADMIN: DLQ list, poison-message demo). **No business `if`s here.**
- `negocio` — `@Stateless` EJBs `GestionTurnos`, `GestionPacientes`, `GestionProfesionales`, `FachadaReservas`, `GestionNotificaciones` (what the JMS consumers do), `MonitorSalud`, `LimpiezaIdempotencia` (`@Schedule` timer); the `@Stateful` `AsistenteReservaTurno`; `FabricaTurnos`; domain exceptions; `CargaDeDatosDemo` (idempotent seed data at startup).
- `datos` — repository interfaces; `datos.jpa` implementations are active, `datos.memoria` ones are `@Alternative` (plan B without DB: enable `<alternatives>` in `beans.xml` and remove `persistence.xml`).
- `modelo` — JPA entities shared by all layers. The only behaviour is the **State pattern** in `modelo.estado`: `Turno.cancelar/atender/archivar()` delegate to `EstadoTurno.comportamiento()`; invalid transitions throw `TransicionInvalidaException` → **409**. Never change a turno's state with `setEstado` outside the state classes / `FabricaTurnos`. Relations are **unidirectional** (Turno → Paciente/Profesional) so entities serialize directly to JSON without output DTOs; keep it that way to avoid cycles.
- `seguridad` — JWT (HS256, JDK + JSON-P only): `ServicioJwt` emits/validates, `MecanismoAutenticacionJwt` is a Jakarta Security `HttpAuthenticationMechanism` that calls `notifyContainerAboutLogin(user, groups)` and writes its own 401 (Problem Details + `CabecerasSeguridad.aplicar`, because it runs before servlet filters). `CabecerasSeguridad` (`@WebFilter("/*")`) sets CSP/nosniff/X-Frame/Referrer/Permissions/CORP/COOP/HSTS and `no-store` on the API; `SameSite=Strict` on JSESSIONID comes from `WEB-INF/undertow-handlers.conf` (web.xml 6.0 has no such attribute and Undertow ignores `SessionCookieConfig.setAttribute`).
- `mensajeria` — `DestinosJms` declares queue `ColaConfirmaciones`, topic `TopicoRecordatorios` and DLQ `MensajesFallidos` via `@JMSDestinationDefinition`; `NotificadorTurnos` sends an `EventoTurno` (versioned JSON built with JSON-P, ids only, no personal data, persistent, props `eventoId`/`tipoEvento`/`versionEvento`/`turnoId`) through `java:/JmsXA` (XA, enlisted in the JTA tx). The three MDBs go through `ConsumoDeEventos.procesar`: parse/validate, call an idempotent `GestionNotificaciones.registrar*` (dedupe by `(eventoId, tipo)`), and on any failure `setRollbackOnly()` — **never swallow errors in an MDB**. Redelivery (4 attempts, backoff 1/2/4 s) and DLQ routing are Artemis address-settings in `scripts/wildfly/configurar-mensajeria.cli` (addresses `jms.queue.<destinationName>` / `jms.topic.<destinationName>`); `MonitorMensajesFallidos` records DLQ messages. Topic MDBs use durable subscriptions (`maxSession=1`).
- `integraciones` (Entrega 2) — Adapter pattern: `ValidadorCobertura` interface, `AdaptadorObraSocialLegado` (SOAP client) and `AdaptadorObraSocialPartner` (REST client), `GestorCobertura` picks one by obra social (PAMI/OSDE/IOMA → legacy SOAP, others → partner REST). `integraciones.simulacion` holds the simulated external systems inside the same WAR: a `@WebService` EJB (`/ServicioObraSocialLegadoImpl?wsdl`) and a REST app under `@ApplicationPath("/partner")`, deliberately outside the security constraint. Adapters must call them via URL/WSDL, never by direct class reference. Adapters need `@LocalBean` because `GestorCobertura` injects them by concrete class.
- `integraciones` — AI specialty assistant (step 1 of the wizard, "Prefiero escribirlo"): `GestorOrientacion` (`@Stateless`, `@RolesAllowed` PACIENTE/RECEPCION/ADMIN) validates the client-sent conversation (`MensajeChat`, stateless — nothing stored server-side), passes the active specialties to `OrientadorEspecialidad` (Adapter) and discards any suggested specialty not in that list. `AdaptadorIaGroq` calls an OpenAI-compatible chat-completions API (Groq by default) with `response_format=json_object`; key from `-Dmediconecta.ia.clave` / `MEDICONECTA_IA_CLAVE` (never in the repo or the browser), optional `mediconecta.ia.modelo` / `mediconecta.ia.url`. Endpoint `POST /api/reserva/orientacion`; picking the suggestion still goes through `PUT /api/reserva/especialidad`.

Key cross-cutting rules:

- **Authorization lives in the business layer** (`@RolesAllowed` on EJB methods, role names in `negocio.Roles`), not on REST resources, so it applies to every caller. Authentication is a JWT in `Authorization: Bearer` (no `<login-config>`; `jboss-web.xml` binds the WAR to security domain `other`, which needs `integrated-jaspi=false`). Public: `/api/salud`, `/api/auth/*`, and the static `/app/*` pages (JS redirects to `login.html` without a token). Ownership checks that roles can't express (a PACIENTE seeing only their own data, a MEDICO editing only their own availability) are done programmatically via `SessionContext.getCallerPrincipal()` — e.g. `GestionPacientes.exigirPropioDocumentoSiEsPaciente`.
- Errors are **Problem Details (RFC 9457, `application/problem+json`)**, built only in `presentacion.Problemas` from the catalog `TipoProblema` (`type` = `urn:mediconecta:problema:<id>`): `ReglaNegocioException` 400, `NoEncontradoException` 404, `TransicionInvalidaException` 409, `ConflictoIdempotenciaException` 409/422, `CredencialesInvalidasException` 401, `EJBAccessException` 403, `IntegracionExternaException` 502 or 504 when `esPorTiempo()`, malformed JSON 400, JAX-RS errors `about:blank`, anything else 500 with an `idError` (no internal message). Business code has no HTTP knowledge. A new error kind = new `TipoProblema` + branch in `Problemas.de` + entry in `openapi.json`. The frontend reads `detail`.
- `POST /api/turnos` supports `Idempotency-Key` via `FachadaReservas.reservarConClave` (per user, 24 h, SHA-256 of the normalized `SolicitudTurno`, stored in `claves_idempotencia` in the same tx; replay → same turno + `Idempotent-Replayed: true`).
- Every outbound call has timeouts: `integraciones.TiemposDeEspera` (REST/SOAP clients, 2 s connect / 5 s read, `mediconecta.integraciones.timeout.*`), the IA adapter its own (5/30 s); server side JTA 60 s, HTTP, pool 5 s (`configurar-limites.cli`), JPA queries 5 s (`persistence.xml`). The SOAP client uses the WSDL bundled in `src/main/resources/wsdl/` and sets the endpoint from `mediconecta.soap.url` (legacy `mediconecta.soap.wsdl` still accepted).
- `openapi.json` (OpenAPI 3.1, hand-written) is checked by `ContratoOpenApiTest` against every `Recurso*` method: adding/changing an endpoint without updating the contract breaks the build.
- Transactions are container-managed JTA per EJB method; repositories never begin/commit. `FachadaReservas.reservar()` is the single entry point for booking (used by both `POST /api/turnos` and the stateful wizard) and runs patient resolution, turno creation and JMS sends in one transaction.
- Every `Turno` must be created through `FabricaTurnos.crear(...)` (forces `PROGRAMADO`, truncates `fechaHora` to the minute, checks specialty coherence). Bypassing it breaks the overlap rule.
- The stateful wizard is bound to the HTTP session by `ConversacionDeReserva` (`@SessionScoped`, holds `Instance<AsistenteReservaTurno>` so it can destroy and recreate it).
- `Turno.fechaHora` uses `@JsonbDateFormat("yyyy-MM-dd'T'HH:mm")` to keep the API contract without seconds. `POST /api/turnos` accepts both the legacy body (embedded paciente + profesional name) and the short one (`documentoPaciente`, `profesionalId`, `fechaHora`) — see `PedidoTurno`.
- Schema is owned by **Flyway migrations in `db/migraciones`** (run outside the WAR: Maven plugin, compose `migraciones` service, CI job); Hibernate only validates (`hbm2ddl.auto=validate`). Any entity change needs a new `V<n>__descripcion.sql` whose types match what Hibernate expects (`timestamp(6)` for `LocalDateTime`, `varchar(n)` with the `@Column` length, identity ids) — never edit a published migration. New entities must also be listed in `persistence.xml`. Datasource `java:/jdbc/MediConectaDS` is defined in WildFly, never in the repo.

## Frontend

`src/main/webapp`: plain HTML + CSS + native ES modules, no framework, no build step (intentional). One HTML page + one JS module per screen under `app/` and `js/`; shared modules `api.js` (derives context root from `import.meta.url`, keeps the JWT in `sessionStorage` and sends it as `Authorization`, reads Problem Details `detail`, `nuevaClaveIdempotencia()`), `ui.js`, `layout.js` (draws sidebar/topbar). Escape all server data with `esc()` before inserting into HTML. **The CSP forbids inline scripts, inline `style="..."` attributes and external origins** (except Google Fonts): use classes from `styles.css` (utilities `u-*`) and `element.style` from JS. `api-docs.html` (Swagger UI from jsDelivr with SRI) has its own relaxed CSP.
